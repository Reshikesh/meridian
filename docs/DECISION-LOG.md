# Technical decision log (Claude Code appends; one line per decision: what, why, phase)


## Phase 0

1. **`data-theme` lives on `<html>`, not the app root div** — the pre-paint script cannot target a div Preact has not created yet; the mockup's placement makes a theme flash unavoidable. (phase 0)
2. **localStorage key `meridian:theme`, raw string** — CLAUDE.md mandates the `meridian:` prefix; a raw string means the pre-paint script needs no JSON parsing and cannot throw on malformed data. (phase 0)
3. **The page frame `#d9d5cd` is tokenised to `var(--bg)`** — the mockup hard-codes it outside the theme blocks; kept literal, graphite gets a light-beige surround and the page flashes light before paint, breaking QUALITY-BAR §3 and §7. (phase 0)
4. **`box-sizing: border-box` globally** — without it the 1180px container plus its two 1px side rules is 1182px of layout width, producing a horizontal scrollbar at a ~1181px viewport. (phase 0)
5. **Screens cross-fade by stacking two in a grid cell for 120ms; outside a switch only the active screen is in the DOM** — `display` cannot be transitioned, so the mockup's show/hide-all-six approach cannot produce the cross-fade QUALITY-BAR §3 asks for, and six always-mounted screens would work against the Phase 5 render budget. Rendering only the incoming screen was the first attempt and was wrong: it is a fade-in from blank, not a cross-fade. No entry animation plays on first load, so there is no fade-up from empty content. (phase 0)
6. **One breakpoint at 1024px** — below it the header groups become `display: contents` so the header can wrap, the nav wraps to its own full-width row, and the gutter drops 28→16px. The mockup has no breakpoints and its header's intrinsic width is ~930px. (phase 0)
7. **Focus rings are `--navink` in the header, `--brand` elsewhere** — `--brand` (#8c1c2b) on the paper header (#1a1614) is 1.98:1, an invisible ring. Defined once in base.css, never per component. (phase 0)
8. **Every font declaration names `Archivo, "Archivo Fallback", system-ui, sans-serif`** — the mockup's `font:` shorthand names Archivo alone, so a font failure would drop the whole app to the browser's default serif. (phase 0)
9. **The metrics-matched fallback face is measured, not guessed, and matches height exactly but width only approximately** — `size-adjust: 98.68%`, `ascent-override: 88.97%`, `descent-override: 21.28%`. The ascent/descent overrides make the `line-height: normal` box height exact at every weight (0.00px delta; raw system-ui is 4px taller), which is what prevents the page reflowing vertically on swap. `size-adjust` is calibrated by layout measurement at weight 400 on a representative line and is exact there, but the ideal ratio is weight- and string-dependent, so heavier weights still differ — about 6% at `700 40px`. One face is the right trade for a font that loads from local disk. (phase 0)
10. **`src/core/` modules use a guarded IIFE footer** — `window.Meridian.<name>` in the browser, `module.exports` under `node --test`. Satisfies "no build step" while keeping core logic unit-testable; the cost is a dependency-ordered script list in index.html. (phase 0)
11. **Unit tests use `require`, not `import`** — `cjs-module-lexer` cannot see named exports through the IIFE, so a named ESM import fails. (phase 0)
12. **`node --test "tests/unit/**/*.test.js"` with the glob quoted** — a bare directory argument fails on Node 24, and cmd.exe does not expand globs on Windows. (phase 0)
13. **Unit files are `*.test.js`, Playwright files `*.spec.js`** — a bare `node --test` would otherwise try to execute the Playwright specs and crash on `require('@playwright/test')`. (phase 0)
14. **The responsive matrix compares against `documentElement.clientWidth`, not `window.innerWidth`, and runs each mandated width also minus 15px** — headless has no scrollbar, so `innerWidth` would hide real overflow that the owner's headed window shows. 1181px is added for the container-plus-borders edge case. (phase 0)
15. **Screenshots at 360 and 1280 only (36 per browser)** — the other eleven widths still run all three checks; 108 shots per run exceeds what a human will actually review, and QUALITY-BAR §8.1 requires them to be looked at. (phase 0)
16. **Playwright runs chromium + msedge; firefox is gated behind `MERIDIAN_FIREFOX`** — Playwright's Firefox and full-Chromium binaries cannot launch on this machine (Windows SideBySide activation-context failure); the project is one env var away when that is fixed. (phase 0)
17. **`timezoneId: 'UTC'` in the Playwright config, with explicit `…Z` instants** — otherwise a frozen-clock test parses the instant in Node's timezone and renders it in the browser's, landing a day early. (phase 0)
18. **Week numbers are padded to two digits (`W01`)** — ISO 8601 writes them padded and the workbook's `iso_week` column is `2026-W22`; no single-digit example exists in any source. (phase 0)
19. **The day boundary uses local calendar-field arithmetic, not `now − 4h`** — a DST transition day is 23 or 25 hours long, so subtracting a fixed four hours lands on the wrong calendar day. (phase 0)
20. **The header stamp recomputes on `visibilitychange` and once a minute**, returning the previous string unchanged so Preact bails out — a tab left open across 04:00 would otherwise show a stale date. (phase 0)
21. **`vendor/xlsx.full.min.js` is vendored now but its `<script>` tag waits for Phase 1** — 952KB parsed on every load for a file nothing uses works against the Phase 5 "2,000 entries under 200ms" budget. (phase 0)
22. **SheetJS pinned to 0.20.3 from cdn.sheetjs.com** — SheetJS no longer publishes to npm, where `xlsx` is frozen at 0.18.5 (three years stale, pre-dating the 0.19.x prototype-pollution fixes). (phase 0)
23. **Archivo vendored as four static instances, obtained via a legacy-UA css2 request** — Google Fonts serves a *variable* font to modern browsers, in which all four weights are one file whose default weight is 600. Verified static by the absence of `fvar`/`gvar`/`avar`. (phase 0)
24. **Inline `data:` favicon in index.html** — stops a headed browser requesting `/favicon.ico`, which would show as a failed request in the owner's devtools during the offline check. (phase 0)
25. **Default screen is `went`; screen state is not persisted** — spec §1 marks "Where it went" as the default and the mockup root is `data-screen="went"`; spec §1 also states the analysis range is the only persisted state. (phase 0)
26. **The token contrast audit ships as a Phase 0 unit test** — QUALITY-BAR §7 asks for an automated check on the token table, and the token table lands in this phase. It records the three sub-4.5:1 pairs rather than changing tokens, which CLAUDE.md forbids. (phase 0)
27. **The responsive audit waits for `document.getAnimations()` to finish and asserts a floor on the leaf count** — the screen cross-fade starts the incoming screen at `opacity: 0`, and the auditor treats an opacity-0 ancestor as invisible, so auditing immediately after a nav click silently degraded to a header-only check on most screens. The leaf floor makes that failure mode loud instead of silent. (phase 0)
28. **The theme is persisted in the click handler, not in an effect** — QUALITY-BAR §6 requires every mutation to reach localStorage synchronously in the same event, and an effect keyed on `[theme]` also skipped entirely when the clicked theme equalled current state, discarding a deliberate choice. `src/store.js` lands next and would have inherited the shape. (phase 0)
29. **`.themes` wraps below 1024px** — its ~241px intrinsic width overflows a layout viewport under ~273px, which 360px at 150% zoom reaches. Found only after adding the zoom axis. (phase 0)
30. **`tests/e2e/zoom.spec.js` covers the zoom axis (90/125/150% × 360–2560px × 3 themes)** — QUALITY-BAR §2 mandates those zoom levels and the width-only matrix never exercised them. Browser zoom scales CSS pixels uniformly, so a W-pixel window at zoom Z is emulated as a W/Z layout viewport. (phase 0)
31. **`.gitattributes` marks `vendor/**` as `-text`** — Git's autocrlf would otherwise rewrite the vendored JS on checkout and break every sha256 recorded in `vendor/README.md`. (phase 0)
32. **The stamp reserves no extra width** — `dd.mm.yyyy / W##` is fixed-width (day, month and week all padded) and the span is `tabular-nums`, so a `min-width` guard against layout shift was unnecessary and pushed the theme toggle ~8px left of the reference. (phase 0)

## Phase 1

33. **Core modules with dependencies resolve them in the UMD footer** (`isNode ? require('./dates.js') : root.Meridian.dates`) — keeps `src/core/` loadable both as classic scripts and under `node --test`, at the cost of a dependency-ordered script list in `index.html`. `dates.js` first, `workbook.js` last. (phase 1)
34. **`workbook.js` takes the SheetJS namespace as a parameter** — `require()` of the vendored UMD sets no global in Node, so a bare `XLSX` identifier would work in the browser and fail every unit test. It also keeps `src/core/` free of globals. (phase 1)
35. **`vendor/xlsx.full.min.js` loads in the vendor block, before `src/`** — measured at ~160 ms total load, and `src/ui/app.js` renders at load, so moving the parse after it would buy nothing and would risk a core module reaching for a namespace that is not there yet. This settles the position left open in #21, not the presence. (phase 1)
36. **Workbook reads use `{cellDates: false, raw: true, defval: null, header: 1}`, and Excel serials are decoded through `XLSX.SSF.parse_date_code`** — `cellDates: true` returns UTC-midnight `Date`s, which local getters then report as the day before for every tester west of UTC. SSF carries no timezone at all. (phase 1)
37. **Columns are read by header NAME, never by index; unknown columns are ignored with a note** — decision 5 invites the friend to edit in Excel, where reordering columns is normal. The note says out loud that unknown columns are lost on the next export. (phase 1)
38. **A workbook is recognised by its zip magic bytes (PK 03 04) before SheetJS sees it** — SheetJS does not throw on a text file; it parses it as CSV and returns a workbook with one nonsense sheet, which would then be reported as "no Categories sheet" instead of "this is not a workbook". (phase 1)
39. **"Round-trips exactly" means app export -> import -> app export** — a hand-edited file cannot round-trip byte-for-byte, because import legitimately normalises (`More` becomes `more`, whitespace trimmed, serial dates decoded). `schema_version`, `app_version` and `exported_at` are stamped at encode time, never held in state, and land in the import report. (phase 1)
40. **`null` is the single representation of empty, in state and in the workbook** — never `undefined`, never `''`, never an absent key. Deep-equal is unforgiving and a spreadsheet cell has one kind of blank. `weekly_cap_hours` blank stays blank (decision 13): materialising the default would change the next export. (phase 1)
41. **`canonical()` orders every array on the way out and on the way in** — categories by `(sort, id)`, entries by `(date, id)`, the rest by `id`; the store re-canonicalises on every mutation. Without it, comparing two states compares two insertion histories. Nothing is ever ordered by id for display. (phase 1)
42. **Pace is hours in the last `k` whole seven-day blocks divided by `k`, where `k = max(1, floor(span / 7))`** — spec §7's Goal has no `created_at`, and every other reading (span since the first entry, a fixed trailing 28 days, ISO weeks) moves a landing date by up to twenty days depending on which weekday the friend first opened the app. Verified stable across all seven. (phase 1)
43. **`categoryPace` uses the identical window with the category as its subject** — the New goal sheet's reachability line and the Goals table are two clicks apart and must not disagree. (phase 1)
44. **"Not enough history" is fewer than seven distinct logged days FOR THAT GOAL** — BUILD-PLAN's number. Counted globally, a goal with one entry inside a busy month would project confidently from that entry. Seven distinct days also span at least seven calendar days, so this satisfies spec §12's "once at least one full week exists" as well. (phase 1)
45. **The landing day is `ceil()` of a value rounded to six decimals first** — `116 / 7 * 7` is `116.00000000000001`, and a bare ceiling would put the landing date a whole day later for a reason no reader could ever find. Caught by a test, not by inspection. (phase 1)
46. **`weeksRunning` counts consecutive ISO weeks backwards per goal, starting at the previous week when the current one is still empty** — without the grace the streak reads zero every Monday morning and reappears after the first entry of the day. (phase 1)
47. **Projection edge cases are decided in core, not per caller**: zero pace gives no landing and no slippage, never `Infinity`; banked at or above target is done with slippage 0, and the percentage is not clamped (the bar clamps in CSS); a `by_date` at or before today gives no required rate rather than a negative one. (phase 1)
48. **Validation splits by caller: strict on creation, forgiving on import** — the waking-hours day cap (§8.17) and a goal date that has already passed are creation-path rules. On import they become notes: a row describing hours somebody actually lived is never discarded (decision 5, and "nothing may be lost"). What import does reject is a row it cannot understand — a duration that is not a number, a date that is not a date, a key pointing nowhere. (phase 1)
49. **Waking hours are `24 - settings.sleep_hours_per_day` everywhere, never a literal 16** — the friend can edit that setting in the workbook. Nonsense values fall back to the default rather than producing a negative day. (phase 1)
50. **Hours format as `Math.round(minutes / 6) / 10`, never `(minutes / 60).toFixed(1)`** — `(0.15).toFixed(1)` is `"0.1"`, so nine minutes would display as 0.1 h. The seed's half-hour grid hides this; `90m` and "Other" will not. (phase 1)
51. **The direction split derives upkeep as the residual (spec §4b)** — rounding three parts independently lets the labels total 101 % and the caption's hours miss the total by an hour. The bar's own width uses the unrounded remainder, clamped, so a rounding residual can never paint a negative segment. (phase 1)
52. **"No goal" sorts among the goal bands rather than being pinned last** — it is a band like any other, and on real data it is usually the largest (spec Appendix B, item 3). (phase 1)
53. **"No future date" compares against the LOGICAL today** — at 02:30 on 8 June, the 7th is today and the 8th has not started. `created_at` and `date` may legitimately differ by a day; neither is derived from or validated against the other. (phase 1)
54. **IDs: semantic slugs for the seed (`cat_learn`, `goal_py`), zero-padded counters at runtime (`e_0001`)** — spec §7 uses both, and a friend typing a `category_id` into an Entries row should read `cat_learn`. `nextId` scans everything already taken, survives non-conforming ids, grows past four digits, and never reissues a gap. IDs are never regenerated on import, which would break every foreign key. (phase 1)
55. **The import cascade is Categories -> Goals -> Entries -> Plan -> Lessons, and duplicate ids within a sheet are rejects rather than last-one-wins** — a silent overwrite is the one import failure the friend could not detect afterwards. (phase 1)
56. **A missing or wholly rejected Categories sheet, an unreadable file, or a newer `schema_version` is the "import failed" state; every other absence is a note** — every entry and goal points at a category, so without one there is nothing to read. An older schema imports with a note saying it will be written back as the current one. (phase 1)
57. **`meridian:theme` stays a raw string in its own key, everything else lives under `meridian:data`, and `meridian:range` is renamed from the mockup's `meridian.range`** — the pre-paint script in `index.html` must never JSON.parse (see #2). (phase 1)
58. **Choosing a theme syncs into `settings` without moving the unexported counter** — the workbook carries the theme so a dataset is portable, but picking one is a display preference, not an edit. (phase 1)
59. **Loading demo data opens at zero unexported changes; a completed import counts as one** — a regenerable dataset shouting "85 unexported changes" on first open is a false alarm, and an import is one deliberate act rather than one act per row. (phase 1)
60. **Every localStorage access is wrapped, and a failed write surfaces as an error the friend can act on** — the property can be `null` (a `typeof` guard passes and then throws), a write can throw `QuotaExceededError` at around 5 MB, and a blocked origin throws `SecurityError`. Unreadable saved data starts fresh but is left on disk, so a hand recovery is still possible. (phase 1)
61. **Export goes through `Blob` + `URL.createObjectURL` + an appended `<a download>`, revoked on a later tick** — the same bytes then feed the download and the export bookkeeping, and the filename is ours. Revoking in the same tick cancels the download in Firefox. (phase 1)
62. **The export filename carries the date alone** (`meridian-data-2026-06-07.xlsx`) — Chromium rewrites `:` in a download name, so an ISO datetime would reach the disk as `09_12_00`. (phase 1)
63. **The demo badge is the header control's own label (`DEMO` rather than `DATA`), not a separate chip** — measured: the 1180 px container leaves 1122 px of content width, and wordmark 81 + nav 378 + themes 241 + control 232 + a 94 px chip + gaps needs 1179 px. A chip does not fit at ANY viewport width, because the container is capped. The full `DEMO DATA` badge and Start fresh live in the sheet the control opens. (phase 1)
64. **The header's wrap breakpoint moves from 1024 px to 1180 px; the gutter and heading scale stay at 1024 px** — the header now also carries the indicator QUALITY-BAR §5 requires and spec §10 has no room for. It fits at the design width and at the 1280 px reference, and nowhere below, so the nav takes its own row from 1180 px down rather than overlapping the theme toggle. (phase 1)
65. **`.themes` gains `max-width: 100%`** — `flex: none` kept the group at its natural width in a viewport narrower than itself, so it overflowed off the LEFT edge and clipped PAPER at 240 CSS px (360 px at 150 % zoom, a real matrix cell). The `flex-wrap` added in #29 was inert without it. A Phase 0 defect, fixed here because the new control lands in the same cell. (phase 1)
66. **`audit.js` gains an off-the-left-edge check, with a matching case in `fixture-broken.html`** — `scrollWidth` only grows rightward, and the existing offender list only ran once the page-scroll check had already failed, so #65's defect was invisible to the harness that exists to catch it. (phase 1)
67. **Busy states are animated in CSS, never through `Element.animate` with an infinite iteration count** — an infinite WAAPI animation never reports `playState === 'finished'`, and both responsive matrices wait on `document.getAnimations()` before every audit. (phase 1)
68. **The directional marks the app needs are drawn as SVG in `src/ui/glyph.js`** — Archivo carries no glyph for a tick, a cross or an arrow, and the vendored subsets strip the arrow, so typing one puts a single character of a different font, at different metrics, in the middle of a line. (phase 1)
69. **The first-run screen takes the whole page, over a header cut back to the wordmark, the theme toggle and the date** — spec §10 requires it to exist "before anything renders", and with no data there is nothing to navigate to. It carries its own leaf floor in `firstrun.spec.js` rather than moving the shell's (#27). (phase 1)
70. **Sheet behaviour (Escape, veil click, focus trap, focus return, first field, scroll lock) ships for Phase 1's own two dialogs, not as a generic API** — BUILD-PLAN assigns the sheets themselves to Phase 2 by name, the stacked category sheet included. The body-scroll lock pays back the scrollbar width as padding, or the page shifts left when a sheet opens. (phase 1)
71. **The four Phase 0 specs seed `meridian:data` through `page.addInitScript`, and only when the key is absent** — an empty browser now means first run, so they had no shell to walk. Writing unconditionally would reset the dataset on every reload, and a test of "this survives a reload" would be testing the fixture. (phase 1)
72. **Workbook fixtures are built at test time from the app's own encoder** — a committed binary fixture goes stale the moment a column changes, and the failure then looks like an importer bug rather than a stale fixture. (phase 1)
73. **`beforeunload` is asserted in the positive case only** — under Playwright the page counts as interacted with before any click, so a "no dialog when there is nothing to lose" test would pass for the wrong reason. The negative case is covered by a unit test on the guard itself. (phase 1)
74. **The seed is keyed to the WEEKDAY, not to an offset from today, and its test sweeps all seven possible first-run weekdays plus a year boundary, both DST switches and the 04:00 edge** — fourteen days hold exactly two of each weekday, so "a complete week is 95.0 h" is true every day; keyed by offset it would be true one day in seven. Today is part-logged, and the entries dropped from it never carry a goal, so both projections read identically whichever day the friend starts. (phase 1)
75. **Spec §9's per-category figures are the seed's PLANNED hours** — decisions 9 and 17 both say so (17: "Work ... its 45 h is its planned hours"), and DECISIONS overrides the spec. §9 [P]'s "plan matching §6" cannot also hold, because the §6 Plan readings imply a different set of planned hours. Lived hours are seeded slightly off plan instead, which is what gives the Manage sheet and the v1.5 Plan screen something to say. Flagged in the phase report. (phase 1)
76. **Reference columns accept the human NAME as well as the id** — `Goals.category_id`, `Entries.category_id`, `Entries.goal_id` and `Plan.category_id` resolve by id first, then by name, case- and space-insensitively; the id is what gets stored, and the report says so, so the next export teaches the convention. Decision 5 makes the workbook a first-class editor and the person editing it is not technical: the Goals sheet asks for a `category_id` while the Categories sheet next door lists eight readable names, so typing `Learning` is the obvious thing to do, not a mistake. Found at the Phase 1 checkpoint, by the owner doing exactly that. A name shared by two categories is rejected rather than guessed at, and a name that matches nothing now says what a working value looks like. Consequence: those four columns read through `asText`, not `asId`, because names contain spaces. (phase 1)

## Phase 2

77. **The Log screen's way in to Manage categories is a button in its day-header row** — the mockup opens that sheet only from the Plan screen, which is v1.5 and renders the calm "coming after your first full week" state, so the sheet Phase 2 builds would have had no door. Log is where categories are chosen all day, so it is where a missing one is noticed. Styled as the mockup's own Plan-screen button (`600 12.5px`, 1px `--line`, `--ink`), which is `.btn` plus `.btn--quiet`. Asked as a product question at the start of the phase and confirmed by the owner. (phase 2)
78. **The Manage sheet counts to 112, not 168** — its `SHARE OF 168 H` column and its footer's "past weeks keep adding up to 168" are both "of N h" figures, which decision 17 makes waking-hours figures; only the Plan screen's own bar keeps 168, because it names sleep out loud. The same call the Log week strip's `97/112 h` already made. Overrides BUILD-PLAN's "footer copy verbatim". (phase 2)
79. **The Log table is five columns, `84px 1fr 128px 152px 40px`** — decision 10 removes VALUE and says its width goes to ACTIVITY, and ACTIVITY is the `1fr` track, so removing a 92px column and its 12px gap does exactly that with no other change. The quick-add `+` moves into the COUNTS TOWARD column, which is what is left where it used to sit; the trailing 40px column stays empty in that row, as in the mockup. Consequence: the `+` is 152px rather than 92px wide. (phase 2)
80. **A bare number in a duration field is HOURS** — `1.5`, `1.5h` and `90m` are the three forms BUILD-PLAN names, plus the spellings a person reaches for by reflex (`hrs`, `mins`, `.5h`, `2H`). Every figure in the app is written in hours and the field's own placeholder is `1.5 h`, so reading a bare `2` as two minutes would be a silent misreading of the commonest input there is. `parseDuration` returns whole minutes or null — never a guess — and `1h30`, `1:30` and `2 hours 30` are refused rather than interpreted. (phase 2)
81. **`+` carries whatever is already in the quick-add row into the sheet** — decision 19 makes the row and the sheet two paths to the same entry shape, so pressing `+` mid-typing is a continuation, not a restart. A duration that is not a preset arrives as "Other". (phase 2)
82. **Unlocking the category and moving off the goal's own category clears the goal** — business rule §8.2 makes the pairing non-negotiable and `validate.validateEntry` would refuse the mismatch anyway; resetting to "Nothing yet" says so before the Save button does. (phase 2)
83. **The COUNTS TOWARD block is omitted entirely when there are no goals** — its copy is about choosing between goals, and a block whose only option is "Nothing yet" is a question with one answer. (phase 2)
84. **SAVING THIS MOVES is shown only with a goal selected, and in edit mode it compares against the state WITHOUT the row being edited** — otherwise raising a 2 h entry to 2.5 h would read as if both existed. Its "before" and "after" both come from `src/core/projection.js`, so the sheet and the Goals table cannot disagree. (phase 2)
85. **The `…` row menu, the archive confirm and the delete confirms all reuse the Phase 1 `.confirm` block** — QUALITY-BAR §4 requires lossy actions to confirm inline in the same visual language, and the import replace-or-keep prompt had already established what that looks like. (phase 2)
86. **Only the topmost sheet answers Escape, tracked by a module-level stack in `sheet.js`** — two sheets each add a capture-phase `keydown` listener to `document`, capture listeners on the SAME node fire in registration order, and `stopPropagation` does not silence a listener on the node it was called from. Without the stack, one Escape closed the stacked category sheet AND the Manage sheet under it. (phase 2)
87. **The Manage row editor renames in place and opens colour, direction and planned hours on a strip underneath** — BUILD-PLAN says "rename in place", and the three other fields have no column of their own to live in. The strip keeps the sheet one level deep, so the stacked-sheet rule stays reserved for New category. (phase 2)
88. **The mockup's dashed `data-fld` underline is kept, and given the editor it never had** — spec Appendix A's complaint is that it promises editability with nothing behind it. On a Log row the activity text opens the edit sheet; in the Manage sheet the category name opens the row editor. Both are the same action as the explicit control beside them, so the affordance is honest rather than decorative. (phase 2)
89. **Category pickers are real `<select>` elements styled to the mockup's box** — the mockup draws a div with a caret, which has no keyboard, no type-ahead and no accessible name. The caret is drawn in SVG because Archivo has no glyph for ▾ at any subset, and `option` gets an explicit background because the dropped-down list is painted by the OS and does not inherit the theme. (phase 2)
90. **The segmented controls, direction cards and swatches are one shared roving-tabindex radio group in `src/ui/fields.js`** — the mockup draws each as a static div with a hard-coded `data-active`, so none of them has a keyboard, a focus ring or a disabled state. One implementation means the three cannot drift apart. (phase 2)
91. **Whether a category swatch gets QUALITY-BAR §7's 1px outline is measured, not assumed** — `src/core/colour.js` computes the WCAG ratio against the theme's own `--bg`, so only the three swatches actually under 3:1 on graphite (#7d2b5d, #2b4a7d, #6b4a7d) are outlined and #c8291a at 3.23:1 is left alone. It carries its own copy of the three `--bg` values because it runs in the browser with no access to the stylesheet; `tests/unit/tokens.test.js` parses `tokens.css` and asserts the copy still matches. (phase 2)
92. **HTML entities are never written inside an `html` template** — htm templates are plain JS template literals and do not decode them, so `&hellip;` renders as the six characters `&hellip;`. Every mark is a real character, and all four the app needs (— … ’ ·) are inside Archivo's latin subset, so none falls back to another face. Found on screen, not by reasoning. (phase 2)
93. **`.sr-only` is an inline-block, not `position: absolute`** — the usual recipe positions against the nearest POSITIONED ancestor, which for a Log row's "No goal" label is `.container`, outside the table's horizontal scroller. It escaped the scroller's clip and stretched the PAGE to 399px at a 345px viewport. One inline pixel cannot. (phase 2)
94. **`.screens > .screen` takes `min-width: 0`** — a grid item's default `min-width: auto` is its content's minimum, so the Log table's own scroller could not shrink below its widest row and the page scrolled instead of the table, which is the opposite of what QUALITY-BAR §2 asks for. (phase 2)
95. **The responsive auditor now compares CLIPPED rects, and ignores visually-hidden boxes** — `getBoundingClientRect` reports where an element WOULD be, clipping or not, so a row scrolled under the edge of its own container read as overlapping whatever was painted beyond it, and a capped sheet with a scrolling body reported its footer colliding with every row below the fold. `visibleRect()` intersects an element's rect with every clipping ancestor and returns null when nothing of it is on screen; checks (i-b) and (iii) use it. An sr-only box — a 1×1 with a clip-path — is skipped outright: it is clipped on purpose and it is 1×1, so it collides with whatever it sits in. ## Decision 31 — unavailable days

239. **`--line2` and `--pale` are the same hex in two of the three themes, which is why a pre-data day looked pickable** — paper `#f0ebe4`, graphite `#26282d`, blueprint 1.03:1 apart. An unpickable day was outlined in exactly the colour an available day is filled with, and both sat 1.08-1.22:1 against `--bg`. Measured before anything was changed, from the token table rather than by eye. The fix attempted was `--ink2` at the `.45` opacity `.btn:disabled` and `.seg__btn:disabled` already use — the app's own disabled language, no new token, the nineteen of spec §5 untouched. Against `--pale` that would be 1.00 to 1.70:1 on paper, 1.00 to 1.97 on graphite, 1.03 to 1.70 on blueprint. **Built, rendered, and withdrawn by the owner — see #248.** The measurement above stands; the change it argues for does not. (decision 31)
240. **The availability rule moved into `range.selectable(day, opts)`** — `calendar.js` decided what to draw with `key >= minDay && key <= today` while `range.pick` refused a click with `day > opts.today || day < opts.minDay`: the same rule, written twice, in a component and in core. That is precisely the split that let the screen draw a cell as pickable and then refuse it. One function now answers both, and it is unit-tested against the day before the first logged day, that day itself, today and tomorrow. (decision 31)
241. **The refusal is a 200 ms held class on the cell, not a keyframe and not a message** — the same two properties the typed-date field reverts with (`--warnbg` background, `--warn` border), for the same reason as #135: base.css collapses every animation to 1 ms under `prefers-reduced-motion`, so a keyframe would be invisible to exactly the people it is for. `--warnbg` is only 1.03-1.11:1 against `--bg`, so as on the field it is the `--warn` border that carries it. One cell at a time: a second refused click moves the flash and restarts the hold. (decision 31)
242. **Attaching the click handler to unavailable cells needed nothing new, because #130 had already chosen `aria-disabled` over `disabled`** — that choice was made so the mockup's hover numerals would still work on future cells, and it is the reason a real pointer reaches these cells at all. `onClick` went from `available ? onPick : null` to a handler that picks or refuses. It is also why the e2e has to click them with `force: true`: Playwright's actionability check reads `aria-disabled` as "not enabled", though a real user is not so careful. (decision 31)
243. **Hover on an unavailable cell drops the brand fill but keeps the numerals** (owner, amendment to decision 31) — hovered, an unavailable day and an available one were pixel-identical: solid `--brand` with a white numeral, the app's strongest "click me" signal, on a cell that then refused. The numerals are the useful half and stay; `cal__num--hover` is withheld with the fill, because `--brandink` is white and there is no brand behind it. A deviation from spec §4d and from the hover half of #130, for unavailable cells only. (decision 31, owner)
244. **`went-predata` needed a `ready` selector unique to its dataset, not `.cal__fill--off`** — the matrix harness asserts a state's `ready` selector returns to zero after `close()`, and the demo has unavailable days of its own, so `.cal__fill--off` never went back to zero and all 39 responsive tests failed. It keys on 3 June being `aria-disabled`, which it is on the two-day dataset and is not on the demo. A `ready` selector has to identify the state, not merely be present in it. (decision 31)
245. **`twoDayState` — two logged days, 6 and 7 June** — the demo has pre-data days too, but spread across two month bands. Filtering the demo to its last two days puts days before the first logged day, available days and future days in a single June band, which is the only arrangement where the three treatments can be compared in one screenshot and audited in one matrix state. (decision 31)
246. **The refusal flash is not screenshotted for review** — it lasts 200 ms, and a `shots.spec.js` capture racing it would produce a review image that is sometimes the flash and sometimes not. `went-predata.spec.js` asserts it on a paused clock instead, which is deterministic; the shots cover the resting and hovered states, where there is no timer to race. (decision 31)
247. **The token test reads the border colour back out of `components.css`** — asserting only against `tokens.css` would not have caught this defect, because no token was wrong: the tokens were fine and the stylesheet reached for the wrong one. `.cal__fill--off` is parsed for its `var(--…)`, which is then checked against the token table for every theme: not equal to `--pale`, at least 3:1 against `--bg`. The test binds the two files together, so editing either alone goes red. (decision 31)
248. **The visible unavailable ink was built, rendered, and withdrawn by the owner** — #239 lifted `.cal__fill--off` from `--line2` to `--ink2` at `.45` on the measurement that `--line2` *is* `--pale` in paper and graphite. It shipped through a full green suite and a v1.1.0 re-cut before the owner saw it on screen and rejected it: the resting calendar should stay quiet. `.cal__fill--off` is back to spec §4d verbatim and its declarations are byte-identical to `1d27aa0`; verified not by reading the diff but by re-rendering the review shots against ones captured from that commit, which come out byte-identical. Recorded here as tried and withdrawn rather than dropped, because the measurement in #239 is still true and a future session that re-measures will reach for the same fix. **The contrast is a decision, not a defect.** What distinguishes an unavailable day is the brand hover it does not take (#243) and the refusal flash (#241) — both kept. (decision 31, owner)
249. **The token test was inverted rather than deleted** — it asserted the unavailable ink differed from `--pale` and cleared 3:1 against `--bg`, which after the withdrawal would fail by design. It now asserts the opposite thing in the same place: `.cal__fill--off` is `background: transparent` with `border: 1px dashed var(--line2)` and carries no `opacity`, and the three ratios it used to police are pinned as literals the way the theme-toggle border above it is. Deleting it would have left the spec treatment unguarded in both directions; inverting it means a silent "fix" of the contrast goes red, and so does a token edit that moves `--line2`. (decision 31)

## Phase 8a — the spike

250. **A `FileSystemFileHandle` survives a browser restart in IndexedDB on `file://`** — measured in Edge 152 and Chrome 152 on profiles that had never granted anything: `origin` is `file://`, `isSecureContext` is true, the handle structured-clones into IndexedDB, and the same profile launched again reads it back live with its name intact. This is the finding decision 32 was waiting on; there is no re-pick-per-session fallback to build. (phase 8a)
251. **The permission, not the handle, is what a session loses** — `queryPermission({mode:'readwrite'})` reads `prompt` on every fresh browser start, `granted` after a grant, and stays `granted` across a page reload within the same browser session. Decision 33's shape is exactly right: one ask per session, not one per write and not one per reload. (phase 8a)
252. **`requestPermission({mode:'readwrite'})` resolves from a form-submit handler** — 893 ms in Chrome, 1.7 s in Edge, both from the submit button's own click. The prompt reads "Allow this site to edit meridian.xlsx?" with **Allow** / **Don't Allow** in both browsers, and the origin renders as a bare `file:///`. (phase 8a)
253. **Don't Allow carries the focus ring, so Enter refuses** — captured in the Chrome screenshot. Every line of copy about that prompt has to say *click Allow*; telling a friend to "press Enter" would deny the grant they were told to give. (decision 36, phase 8a)
254. **A dismissal is not sticky, and neither is a refusal** — Escape resolves `requestPermission` with `prompt` (not `denied`), `queryPermission` still reads `prompt` afterwards, and the next ask prompts again. Clicking Don't Allow behaved the same way on Edge. So decision 33's `SAVE · n` can always ask again; there is no dead end to design around. (phase 8a)
255. **A write attempted without a grant hangs rather than failing** — `createWritable()` on a handle whose permission is `prompt` raises the prompt itself and the promise stays pending until a person answers it: 118 s and 193 s in two runs. The mirror therefore asks `queryPermission` before it writes and goes to `SAVE · n`; firing a hopeful write would stall the queue behind an unanswered bubble. (decision 33, phase 8a)
256. **Five concurrent writes on one handle all report success and the file keeps the second one** — fired together they resolved `ok` five times and left write #2 on disk; run in sequence they leave #5, at ~110 ms each. Decision 32's queue is a correctness requirement, not a politeness. (phase 8a)
257. **Excel does not hold an open `.xlsx`** — it reads the file, releases the handle and leaves a `~$` marker, so `FileShare.None` succeeds against a workbook sitting open on screen and mirror writes go through the whole time. The lock window is only the moment Excel loads or saves. This is what killed the original decision-35 acceptance step. (decision 35, phase 8a)
258. **A genuinely held file rejects the write with `InvalidStateError`** — "An operation that depends on state cached in an interface object was made but the state had changed since it was read from disk", verbatim, under both `FileShare.Read` and `FileShare.None`; reads keep working throughout, and the first write after release succeeds with no re-read and no new grant. `NoModificationAllowedError` never appeared. (decision 35, phase 8a)
259. **Our own write moves `lastModified` to within a few milliseconds of our clock, in either direction** — the file's value came out 3 ms before our clock on one run and 94 ms after it on another, and is stable across repeated reads with no write between. So the recorded "last mirror" is the file's own `lastModified`, read back after each success; a wall-clock comparison would fire decision 34 on the app's own writes. (decision 34, phase 8a)
260. **Chromium marks every file it writes as coming from the internet** — the workbook gains a `Zone.Identifier` stream with `ZoneId=3` and a `ReferrerUrl` naming the local page, so Excel opens it behind the Protected View bar from the first mirror onwards. It cannot be suppressed from the page; decision 36 accepts it and the README explains Trusted Locations. (decision 36, phase 8a)
261. **Firefox 155 has `FileSystemFileHandle` but no picker** — `showOpenFilePicker`, `showSaveFilePicker`, `queryPermission` and `requestPermission` are all `undefined`, while `FileSystemFileHandle` and `createWritable` are functions, because the origin-private file system ships there. A `FileSystemFileHandle in window` feature check would wrongly show the Link controls in Firefox; the check is `showOpenFilePicker`, as decision 32 says. (phase 8a)
262. **Neither Playwright nor raw CDP can reach the file picker** — `showOpenFilePicker` fires no `filechooser` event and no `Page.fileChooserOpened` even with `Page.setInterceptFileChooserDialog` enabled, and the permission bubble is browser UI besides. The 8b e2e therefore stubs both pickers and both permission methods through `addInitScript`; the spike itself drove the real dialogs through Windows UI Automation, which is not something a test suite should depend on. (phase 8a)
263. **Chromium refuses whole folders, `%LOCALAPPDATA%` among them** — a pick under `AppData\Local` is rejected after the fact with "file:/// can't open files in this folder because it contains system files". Nothing to build; it belongs in the tester README beside the advice to keep the workbook in Documents, which is also why Create opens at `startIn: 'documents'`. (decision 36, phase 8a)

## Phase 8b — the linked workbook

264. **The state machine is core, the file handling is UI** — `src/core/link.js` is six states, a reducer, a label and an action, with no DOM and no File System Access API in sight, so every transition is unit-tested in node; `src/ui/link.js` owns the handle, IndexedDB, the pickers and the writes, and reports outcomes back as events. The split is the one `io.js` already makes for the same reason: the only module that needs a document is the one that touches files. (phase 8b)
265. **The store's hook keys on the counter, not on the increment** — `commit` fires the mirror when the unexported counter ends up above zero rather than when `changes` is truthy, because a completed import sets the counter to 1 without incrementing it (59) and would otherwise never reach the file. A theme change, a range write and the demo dataset still move nothing. (phase 8b)
266. **The hook fires last, and only when localStorage took the change** — the live copy is safe before anything touches the disk, and a mirror that throws cannot lose the entry the friend just typed: the call is wrapped, and its failure is a workbook state, never a data error. (phase 8b)
267. **The handle lives in IndexedDB, the record in localStorage** — a `FileSystemFileHandle` is not a string, so localStorage cannot hold it; the file's name, our last write's `lastModified` and when we wrote it go in `meridian:link` beside the app's other keys, because a reload and a second window both need them and neither can read IndexedDB synchronously at load. (decision 32, phase 8b)
268. **`withStore` resolves the request's `result`, not the request** — the first cut resolved the `IDBRequest` itself, which is truthy even when the key is absent, so a browser with no linked workbook came up believing it had one that answered no questions: the header read `SAVE · 1` after a single entry, with nothing to save it to. Caught by `data.spec.js`, which has asserted the export label since Phase 1. (phase 8b)
269. **The write queue coalesces rather than debounces** — a mutation that arrives while a write is in flight sets a flag, and one further write runs when the current one lands, encoding the state as it stands then. Five writes fired at once all report success and leave an arbitrary one on disk (256), so overlapping is not an option; a timer would be the debounce decision 32 forbids. Every mutation is already in localStorage before any of this runs, so the coalesced write is never the difference between kept and lost. (decision 32, phase 8b)
270. **Nothing is written while the permission is `prompt`** — `createWritable` on an ungranted handle raises the browser's own prompt and hangs until someone answers it, for as long as it takes (255): the queue would stall behind a bubble nobody had noticed. `shouldWrite` allows only `auto` and `locked`; `needs-grant` goes to decision 33's `SAVE · n` instead. (decision 33, phase 8b)
271. **The grant is asked for once per session, on the first counted mutation** — inside that mutation's own click or Enter, because a request without a user gesture is refused outright. If it is dismissed, the app does not ask again on the next keystroke: the `SAVE · n` control is the way back, and a prompt that reappears on every entry is how a friend learns to click Don't Allow. (decision 33, phase 8b)
272. **Every write reads `lastModified` first, and records the file's own value afterwards** — the check that decision 34 asks for sits in front of the write rather than only on reconnect, and what it compares against is the number the file reported after our last write, not our clock: the spike measured our clock landing 3 ms early on one run and 94 ms late on another, either of which would have the app mistake its own write for someone else's edit (259). (decision 34, phase 8b)
273. **An unreadable workbook is dealt with at the click, not at the write** — decision 37 C says a file that cannot be read is written over and the friend told. Detecting that at write time would mean decoding the workbook inside every mutation, which is a synchronous parse in the middle of logging an entry; instead the write stops at `EDITED OUTSIDE`, and the decode happens in the click that follows, where the sheet is already showing a busy state. The friend meets one extra click and no dropped frame. (decision 37, phase 8b)
274. **The conflict prompt reuses the import report, with the brand button on Keep local** — decision 15's component, its counts and its rejects, under a different question. The default is reversed from the import case on purpose: nobody asked for this prompt, and what is in Meridian is what they were typing a moment ago, so the emphasis belongs on the choice that keeps it. (decisions 15, 37, phase 8b)
275. **Replace local records the file before it adopts it** — `adoptedFile()` writes the file's current `lastModified` into the record, and only then does the store take the data. The other order fires the mirror hook against a stale record, and the app declares the file edited-outside one moment after agreeing to take it. (decision 37, phase 8b)
276. **The e2e double is a localStorage-backed handle, with IndexedDB patched in the test** — the origin-private file system is refused on `file://` ("certain files are unsafe for access within a Web application"), so a real handle cannot be conjured; a double with methods cannot be structured-cloned into IndexedDB either. `lib/link-stub.js` patches `IDBObjectStore.put`/`get` to carry a marker across the clone and hand back a live double, and keeps the bytes and a counter-based `lastModified` in localStorage — a clock would not do, because these suites freeze time. The patches live in the test; the app has no seam. (phase 8b)
277. **Five matrix states, and an unlink that puts the header back** — `sheet-data-linked`, `header-save-n`, `header-locked`, `header-edited-outside` and `sheet-conflict` run at every width, zoom and theme like every other transient state. Each closes by unlinking and reloading the demo, because a state that leaves a workbook attached would change what the next state is looking at. (phase 8b)
278. **The link prompt is asked only when there is something local to lose** — decision 37 A gated on whether the *file* held a dataset, never on whether the app did, so linking a workbook from the first-run screen raised a two-way prompt whose brand button read `Keep local, overwrite the workbook`: one Enter from writing an empty dataset over the friend's only copy. The gate is now `hasContent(store.getState())`, which is 37 B's own reasoning — a question with one sensible answer is not asked — applied to the moment before it. Found in the owner's screenshots of a real reopen, not by any test. (decisions 37, phase 8c)
279. **The two conflict moments lead with opposite buttons** — an outside edit interrupts work still in the app, so `Keep local` keeps the brand and the autofocus it has had since 274. A link is a file the friend went and chose, holding data counted in the report below, so `Replace local` leads there and the button that overwrites the workbook is the quiet one. Same view, same report, one `reason` prop. (decisions 15, 37, phase 8c)
280. **A mirror write is recorded as a save, not an export** — decision 32 is unchanged, the write still clears the counter, but `exportInfo` now carries `saved_at` beside `exported_at` and the Data sheet names whichever is newer: `Exported 5 hours ago` for the download, `Saved just now` for the workbook. One label read `Exported just now` for something the friend never exported. With no workbook linked `saved_at` is never set and the line reads exactly as it always has. (decision 32, phase 8c)
281. **Superseded by 287 — this did not work.** ~~Both pickers carry one `id`, so the browser reopens them where the workbook was last chosen~~ — `startIn: 'documents'` sent the friend back through four folders on every reconnect, because the workbook does not live in Documents. The remembered directory lives in the browser profile rather than in site data, which is the whole point: a browser set to clear site data on close wipes the handle and the dataset, and this is the one crumb that survives to make recovery a click rather than a hunt. `startIn` stays as the fallback for the first ever pick. Unverifiable by any test — the real picker cannot be driven (262) — so it is checked by hand. (phase 8c)
282. **"Open a workbook" leads the first-run screen where the browser has a picker** — the three original choices were written for somebody starting out, and a browser that clears site data on close meets this screen every single time it starts, with a full workbook sitting on disk. The card spans the row above them and both loads the data and links the file. Absent where `showOpenFilePicker` is, so Firefox and Safari see the three they always saw. (decision 32, phase 8c)
283. **A wipe is named at the moment it is recovered from, because it cannot be detected** — Meridian holding nothing while the workbook holds a fortnight means either a browser that cleared site data on close or a machine meeting the file for the first time, and the two are indistinguishable from inside the page: everything that would have been evidence lives in the storage that was cleared. So there is no detector. The `opened` view says what happened and names the Edge setting, at the one moment the friend is looking at the consequence. (phase 8c)
284. **A blank workbook picked on first run starts empty, in that file** — adopting writes the app's dataset into the file, and on first run there is no dataset to encode: `workbook.encode` would have been handed a null state inside the adopt. `startEmpty()` runs first, so the friend who points Meridian at a fresh `.xlsx` gets the eight categories and a linked file rather than a failed write and `WORKBOOK LOCKED`. (phase 8c)
285. **The lead card sits above the options grid rather than spanning it** — the first cut gave it `grid-column: 1 / -1` inside `.firstrun__options`, which stops `auto-fit` collapsing the empty tracks: the grid resolved five 240px columns at 1280 and the three original cards stopped filling the row they have filled since Phase 1. Caught in the screenshot, not by a test — nothing asserts that a row is full. Outside the grid, the three are byte-for-byte the layout they were. (phase 8c)
286. **`startIn` is dropped from the open picker, because it beats the id it was sitting beside** — 281 set both `id` and `startIn: 'documents'` on `pickExisting`, on the assumption that `startIn` was only a fallback for a first pick with nothing remembered. It is not: a well-known directory wins, so the remembered path never got a look in and the owner reported the picker still opening at Documents. Create workbook keeps `startIn` — opening at Documents is what that one is documented to do, and a workbook is created once. Nothing here is testable: the real picker cannot be driven from Playwright or CDP (262), the e2e double ignores its options entirely, and this was found the only way it could be — by somebody clicking it. (corrects 281, phase 8c)
287. **The picker id does nothing on `file://`, and `startIn` goes back beside it** — 286 removed `startIn` so the id's remembered directory could win. It did not: the owner picked twice more and Edge opened at Documents both times. Chromium keys the remembered directory to the origin, and a `file://` page has nowhere to keep it — the same wall decision 32 works around, and the reason the handle has to live in IndexedDB in the first place. The id is kept because it is free, correct, and would work the day this runs over http; `startIn: 'documents'` is kept because something has to decide the folder and a predictable answer beats whatever the browser last did. Reconnecting after a site-data clear costs a few folder clicks, and nothing else was ever on the table: the handle that would have made it one click is in the storage being cleared. Tried twice, at the device, because no test can reach a real picker (262) — recorded so nobody runs it a third time. (corrects 286, phase 8c)
